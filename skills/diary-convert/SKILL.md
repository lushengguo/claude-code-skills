# 日记格式转换

自动扫描所有yyyy-mm目录下(除了archived)的所有 `.txt` 日记文件转换为格式良好的 `.md` 文件，做轻度润色，然后将原始 `.txt` 文件归档到 `archived/` 目录中。

## 触发条件

当用户提出以下请求时调用此 skill：
- "转换日记" / "convert diary" / "format diary"
- "整理这个月的日记"
- 任何要求对 `YYYY-M/` 目录下的 `.txt` 文件做格式转换的请求

## 执行流程

### 第一步：确定目标文件

1. 如果用户指定了具体文件路径，只处理该文件。
2. 如果用户指定了月份（如"7月"），处理 `YYYY-M/` 目录下的所有 `.txt` 文件。
3. 如果未指定，默认处理当前月份目录（根据 `date +%Y-%-m`）下的所有 `.txt` 文件。
4. 跳过已经是 `.md` 的文件，跳过 `archived/` 目录下的文件。

### 第二步：逐个转换

对每个 `.txt` 文件执行以下操作：

#### 2.1 解析日期

从文件名 `YYYY-M-DD.txt` 中提取年、月、日，构造 Markdown 标题：
```markdown
# YYYY年M月D日 日记
```

#### 2.2 内容格式化

将原始纯文本内容转换为 Markdown，遵循以下规则：

**标题与分隔：**
- 文件顶部添加一级标题（见上）。
- 不同话题/段落之间用空行分隔，保持原文的段落结构。
- 如果原文有明显的主题切换（从一个话题跳到另一个不相关话题），插入 `---` 水平分割线。
  - 判断标准：前后讨论的是完全不同的话题（如从"交易策略"切换到"工作"）。
  - 不要滥用 —— 同一话题下的几个思考点不需要分割线。

**列表格式：**
- 原文使用 `数字.` 开头的行，转为 Markdown 有序列表 `1. ` `2. ` 等。
- 原文使用 `-` 或 `*` 或 `字母.` 开头的子项，转为缩进的嵌套无序列表 `  - `。
- 原文中的 `A:` `B:` `C:` 等子项，同样转为嵌套列表。
- 如果一个编号条目下面有多行连续文本（不是子列表），将这些文本合并为该列表项下的段落（使用缩进保持列表连续性）。

**强调：**
- 对作者的核心观点、重要结论、自我提醒，使用 `**粗体**` 强调。
- 对书名、术语引用使用 `*斜体*`。
- 不要过度强调 —— 整个文档不超过 5-8 处强调为宜。

**引用：**
- 如果原文引用了外部观点（如 DeepSeek 的分析、书中的话），使用 `>` 块引用。

**代码/技术术语：**
- 技术术语如 `Lua`、`Redis`、`RSI`、`布林带` 等保持原样，必要时用反引号包裹。

#### 2.3 轻度润色

在不改变原意的前提下，做以下润色：

**允许的操作：**
- 删除无意义的口头禅填充词，如："就是说"、"然后就是说"、"这个东西"、"那个东西"、"反正"、"怎么说呢"。
- 合并破碎的短句，让表达更流畅。例如："我去了。然后我看到了。然后我觉得" → "我去看了，觉得"。
- 修正明显的打字错误或语序混乱。
- 将过长的、一口气读完的句子适当断句。
- 删除重复啰嗦的表达（同一个意思说了两三遍的，保留最清晰的那一遍）。

**禁止的操作：**
- ❌ 绝不能改变作者的原意、观点、结论。
- ❌ 绝不能删除实质性内容（事件、数据、人名、具体操作细节）。
- ❌ 绝不能改变作者的情感色彩（如自嘲、沮丧、兴奋）。
- ❌ 绝不能添加作者没说过的新内容、新观点。
- ❌ 绝不能把口语化的日记变成正式公文 —— 保持日记的私密感和个人风格。

**不确定时的原则：**
如果某段话你不确定是否算"啰嗦"，**保留原文不动**。宁可少润色，不可改错。

#### 2.4 写入 Markdown 文件

将转换后的内容写入 `YYYY-M/YYYY-M-DD.md`，与原始 `.txt` 文件放在同一目录下。

### 第三步：归档原始文件

1. 确保 `archived/YYYY-M/` 目录存在，不存在则创建。
2. 将原始 `.txt` 文件**移动**到 `archived/YYYY-M/` 下（保持原文件名）。
3. 如果 `git` 可用，运行 `git add` 暂存新 `.md` 文件和归档变动，但**不要 commit**（留给用户自己提交）。

### 第四步：输出摘要

完成后，向用户报告：
- 处理了几个文件
- 每个文件的输出路径
- 归档路径
- 如果有任何跳过/未处理的行或段落，明确告知

## 文件命名规则

| 类型 | 路径格式 | 示例 |
|------|---------|------|
| 原始 TXT | `YYYY-M/YYYY-M-DD.txt` | `2026-7/2026-7-05.txt` |
| 转换后 MD | `YYYY-M/YYYY-M-DD.md` | `2026-7/2026-7-05.md` |
| 归档 TXT | `archived/YYYY-M/YYYY-M-DD.txt` | `archived/2026-7/2026-7-05.txt` |

## 示例

### 输入（原始 TXT 片段）

```
1. 昨晚没睡好, 因为带仓睡觉, 先是一波涨幅突破布林带, 76.85开仓...
2. 今天早会上提了两个建议, 有一个反响很不错...
```

### 输出（Markdown）

```markdown
# 2026年7月2日 日记

1. 昨晚没睡好，因为带仓睡觉。先是一波涨幅突破布林带，76.85 开仓，回调了一小段时间后开始横盘。一开始设了 20U 止损，睡前害怕被扫掉又改成了 50U 止损，4 点多被扫掉然后回调，今天一路到了 80+。
   - **沉痛教训**：结合最近看的查理·芒格的书——
   - 少开仓，没有机会就等机会，频繁交易只会让本金越来越少
   - 遵循巴菲特说的：交易的三个最重要的东西就是 **1. 不亏损本金 2. 不亏损本金 3. 想着怎么做到 1、2**
   - 尽量不持仓过夜，影响睡眠
   - 止损不应该设得太高，如果担心被扫掉，说明开仓位置不是最好的
   - **不该向外移动止损，该是多少就是多少**
   - 痛定思痛，以后只做大插针场景下的回弹和 4h 均值回归，15min 线不构成任何投资建议

2. 今天早会上提了两个建议，有一个反响很不错……
```

## 注意事项

- 本 skill 只处理 `.txt` → `.md` 的转换，不处理已经是 `.md` 的文件。
- 归档操作是**移动**（不是复制），原始 `.txt` 将从月份目录消失。
- 如果 `archived/` 下已存在同名文件，先询问用户如何处理（覆盖 / 跳过 / 重命名）。
- 日记内容均为中文，格式化时使用中文标点（全角逗号、句号等）。
